# 校园网 Portal 逆向与守护

> 三篇文章 + 一套脚本，讲清楚校园网 Portal 认证怎么抓、怎么读、怎么自动化，
> 以及**为什么你以为是学校在踢你，其实多半是你自己的脚本**。

面向宿舍只有有线口、需要让路由器代替电脑完成认证的场景。以深澜（Srun）Portal 为样本，
方法论对锐捷 / Dr.COM / GiWiFi 一类门户同样适用。

## 三个核心结论

**一、登录参数不用猜，前端 JS 里全写着。**
二十多个参数里，`wlanacname`、`vlan`、`timestamp`、`uuid`、`portalpageid` 都不是你能随便填的。
但跳转 URL 的 query 白送了前两个，`PortalJsonAction.do` 现签发后三个。读 `portalUtil.js`
比抓 HTTPS 高效得多——那条"超出一台电脑一台手机"的提示就是这么发现的。

**二、大多数"掉线"不是学校干的。**
一次连续掉线的排查里，101 次"掉线"只有 3 次是校园网侧问题，其余 98 次是本机故障。
决定性证据很朴素：**那段时间连局域网内的路由器 SSH 都连不上**——校园网掉线不可能导致这个。

**三、最隐蔽的掉线来源，是守护脚本自己。**
一天 67 次掉线里，13 次属于这种情况：会话明明还活着，脚本却先 `disconn` 再 `login`，
把好会话主动踢掉。成因是两个写法叠加——调用时带 `--force`，认证前无条件注销。

修复不是"加保活"、不是"缩短探测间隔"，而是**把"什么时候该动手"这个判断修对**：

```
探测失败   ≠   掉线
门户说这个 IP 上没有会话   =   掉线
```

修完之后：探测误判导致的踢会话 0 次/天，会话连续在线 54 分钟以上不掉。

## 快速开始

```sh
git clone <this-repo> && cd campus-portal-reverse/scripts

cp portal-cred.conf.example portal-cred.conf
vi portal-cred.conf              # 填账号、密码、门户域名、BRAS 名
chmod 600 portal-cred.conf

sh portal-login.sh --dry-run     # 只打印参数，不发认证请求
sh portal-login.sh               # 真跑一次
sh portal-daemon.sh --once       # 单轮守护
```

部署到路由器、procd 托管、hotplug、看门狗：见 [`scripts/README.md`](scripts/README.md)。

**先按第 1 篇在你自己的学校把流程走一遍**，再把参数填进配置文件。
直接套用示例值一定跑不通——每个学校的域名、BRAS 名、VLAN、接口路径都可能不同。

## 关于示例数据

| 示例值 | 说明 |
|---|---|
| `portal.example.edu.cn` | 门户域名占位 |

## 适用边界与免责

这套东西能跑通的前提是：**你用的是自己的账号，且你有权使用那个网络。**

明确不做、也不建议做的事：

- 使用他人账号，或绕过计费系统；
- 突破学校设定的设备数限制用于牟利（合租、转卖）；
- 抓取、公开他人的流量或凭证。

需要你知道的风险：

- **多数高校的校园网管理规定明确限制"一账号多设备共享"**，本文的指纹归一化部分
  在技术上属于规避该限制。是否合规取决于你学校的具体条款，请自行确认；
- 自动化认证脚本会代替你持续向学校服务器发请求，频率过高可能被判定为异常行为；
- 修改路由器防火墙 / 透明代理配置有把设备搞成砖的风险（本文记录的 TPROXY 环路
  就导致过看门狗复位）。

内容仅供技术学习与个人网络维护参考。使用造成的任何后果（账号被封、违反校规、
设备损坏）由使用者自行承担。作者不对任何具体环境下的可用性作保证。

如果你学校的条款不允许，正确做法是**不用**，而不是用了之后说没看见这段。
